Making decisions

Building a machine learning system means making a sequence of decisions about the data, the model, and the evaluation. Each decision should be driven by facts: what you know about the data, about the problem, and about how the model will be used. When we make a decision badly, it shows up as a specific type of failure:

  • Failure to fit: the model has high error even on the training data. It does not represent the relationship between features and target well.
  • Failure to generalize: the model has low error on the training data, but high error on held-out validation/test data. It has learned patterns that are specific to the training sample.
  • Failure to deploy: the model does well on the test set, but poorly once it is used for real. The evaluation was overly optimistic.
  • Failure to generate value: the model does well on our metric, but does not achieve the goal we actually care about.

and some decisions (e.g. whether we may use some data at all) can cause harm, legal or ethical problems, even if the model “works”.

For each decision, the third column lists where it was discussed in the lecture handouts (handout name, section title), the relevant homework problems (HW number, problem number), and the relevant lab problems (Lab number, problem number).

How do we handle missing values? First find them (NaN, special values like 0 or -1, and rows that are absent entirely), then understand why they are missing (MCAR, MAR, MNAR), then leave as missing, drop, or impute, so that the data represents the true (unknown) values as well as possible. Failure to deploy. Dropping rows that are not missing completely at random skews the dataset (e.g. dropping all freezing days because temperature is missing below 32°F), so the model, and its evaluation, under-represent some situations it will see in deployment. Failure to fit. Imputing a poor value (e.g. the mean, when we know the missing values are extreme), or leaving a missing value encoded as a “real” value (e.g. 0), can obscure the true relationships in the data. Notes: Working with Data: “Handle missing data”, “Other data quality concerns”. HW: HW1 Q6 (missing data). How do we represent each feature numerically? Ordinal encoding (ordered categories), one-hot encoding (unordered categories), target encoding (categories with many values), bag of words/count vectorizer (text). Failure to fit, if the encoding imposes a structure that is not there (e.g. ordinal encoding of an unordered category forces the model to treat spicy as “between” floral and woody). Failure to generalize, if one-hot encoding a feature with many categories creates many sparse features, it can lead to overfitting (target encoding is an alternative). What do we compare against? A simple baseline, e.g. prediction by the mean (\(\text{R2} = 0\)), or “same value as last week”. Failure to generate value. Without a baseline, we can’t tell whether the model adds anything over a trivial approach. A model that doesn’t beat the baseline adds cost and complexity, but no value. A negative R2 means the model is worse than predicting the mean. Notes: Linear Regression: “Prediction by mean”, “Interpreting R2 as error relative to”mean model”“. Which metric? MSE/RMSE, MAE, MAPE, R2; choose the one that reflects what errors actually cost in the application. Failure to generate value, if we optimize and report a metric that doesn’t reflect the goal: e.g. a model with better R2 can lose more money. Different metrics weigh errors differently (squared error emphasizes large errors; MAPE emphasizes errors on small values; a few very expensive homes affect MAE and MAPE very differently). Notes: Linear Regression: “Interpreting MSE, MAE”, “Interpreting R2 as explained variance”, “Interpreting R2 as error relative to”mean model”“. Compare training and validation error to diagnose the problem before deciding what to change. Choosing the wrong fix. Both errors high: failure to fit (high bias), so add features, a more flexible model, or less regularization. Training error low but validation error high: failure to generalize (high variance), so get more data, use fewer features, a less flexible model, or more regularization. Note that getting more data reduces variance, but does not reduce bias: if the training error is already high, more of the same data won’t help. Notes: Error decomposition, bias-variance tradeoff, model selection: “When learning fails”, “Error decomposition”, “Bias-variance tradeoff”. Inspect the residuals, not only a summary metric: residuals vs. each feature, vs. prediction, and over time. Undetected failure to fit. A single number can hide a systematic pattern (a missing cycle, a missing group effect, a trend over time) that tells us how to improve the model. Notes: Linear Regression: “Residual term”. HW: HW2 Q2 (residuals graphically), HW2 Q5 (residual plots → feature engineering). Lab: L2 Q2-5 (residual plots for each Citi Bike model), L4 Q3-4 (residuals over time), L4 Q7 (reflection).
Keep the test set independent: use it once, for the final evaluation, after model selection and preprocessing were done with training data only. Failure to deploy. If the test set influences preprocessing, training, or model selection, the test score is overly optimistic. Notes: Working with Data: “Model training vs evaluation vs deployment”, “Split data”; Error decomposition, bias-variance tradeoff, model selection: “Model selection problems”, “Hold-out validation”. HW: HW1 Q8 (train/test/deploy), HW4 Q11 (standardize after split). Lab: L4 Q5-6 (CV on training data, then evaluate the selected model on the test set).
Does the evaluation reflect deployment? Same kind of samples, same information available at prediction time, same prediction horizon, and the outcome we actually care about. Failure to deploy. If the test data differs from deployment data, the model that is best on the test set may not be best in deployment. A forecast evaluated using information that won’t be known yet at prediction time (e.g. tomorrow’s weather) looks better than it will be. Notes: Working with Data: “Model training vs evaluation vs deployment”, “Representativeness concerns”; Intro to ML: “ML training vs reality”. HW: HW1 Q8 (train/test/deploy), HW4 Q13-14 (Parkinson’s speech tests). Lab: L3 Q7 (market simulation), L3 Q8 (Zillow Offers), L4 Q8 (forecast horizon).
How do we turn predictions into actions? A prediction is usually an input to a decision (e.g. offer price = estimated price minus an offset), and the outcome depends on that decision and on how other people respond to it. Evaluate the decision by the outcome we care about (e.g. profit), not only by the prediction error. Failure to generate value. The same model can make or lose money depending on how its predictions are used. When others choose whether to accept our decision, they accept it most often when it is in their favor (e.g. sellers accept offers on homes that the model over-estimated), so the outcomes we actually experience can be much worse than the average prediction error suggests. Apply the one-SE rule to choose a model. For each model \(p\), compute the mean score across the \(K\) folds \(\bar{S}_p\), the standard deviation \(\sigma_p\), and \(SE_p = \frac{\sigma_p}{\sqrt{K-1}}\). Find the best model \(p^*\). For a lower-is-better metric (e.g. MSE), the target is \(\bar{S}_{p^*} + SE_{p^*}\) and candidates have \(\bar{S}_p \leq\) target; for a higher-is-better metric (e.g. R2), the target is \(\bar{S}_{p^*} - SE_{p^*}\) and candidates have \(\bar{S}_p \geq\) target. Then choose the simplest candidate: fewest features, smallest lag order, or largest regularization strength \(\alpha\). General facts

Controlling the bias-variance tradeoff

Most models have one or more “knobs” (hyperparameters, or choices about features) that control how complex a function the model can learn. Turning a knob toward a more complex model usually decreases bias and increases variance; turning it toward a less complex model usually increases bias and decreases variance.

To decide which way to turn a knob, compare training and validation error (see the Evaluation table above). If both are high, the model is on the “too simple” side, so make it more complex. If training error is low but validation error is high, the model is on the “too complex” side, so make it less complex. In the classical view, validation error traces a U-shape as complexity increases, and we choose a knob setting near the bottom of the U (using cross validation, and the one-SE rule to prefer the simpler side). (The Error decomposition handout also shows an “updated view”, double descent, where test error can decrease again for very complex models.)

Facts by topic

Fact Where we saw it
Error decomposition, bias, and variance
For squared error, the expected test error of a model (averaged over random draws of the training set) is bias\(^2\) + variance + irreducible error. The irreducible error (the noise variance \(\sigma^2\)) cannot be reduced by any model that uses the same features. Notes: Error decomposition, bias-variance tradeoff, model selection: “Sources of prediction error”, “Error decomposition”. HW: HW4 Q3. Practice: Q34.
Under-modeling causes bias: if the true function is not in the model class, the model is biased no matter how much data we have. Notes: Error decomposition, bias-variance tradeoff, model selection: “Bias of linear model”. HW: HW4 Q2-3. Practice: Q32-34.
If there is no under-modeling in an OLS regression, the expected parameter estimate \(E[\hat{\mathbf{w}}]\) is equal to the true parameters, but (when there is noise, \(\sigma^2 > 0\)) the estimate from a finite training sample is not exactly equal to them. Notes: Error decomposition, bias-variance tradeoff, model selection: “Bias of linear model”, “Variance of linear model”. Practice: Q38.
For a linear model with no under-modeling, the variance of the model output, on average over test points, is about \(\sigma^2 p / N\): it increases with the noise variance \(\sigma^2\) and the number of parameters \(p\), and decreases with the number of training samples \(N\). Notes: Error decomposition, bias-variance tradeoff, model selection: “Variance of linear model”. Practice: Q36-38.
A model class that contains the true function does not always have lower test error than a simpler one: when the noise variance is high (or there is little data), a simpler, biased model can have lower test error, because it has lower variance. HW: HW4 Q3. Practice: Q34, Q36-37.
Adding a feature (and re-fitting with least squares) cannot increase the training MSE, but it can increase the test MSE. Even a feature that is completely unrelated to the target changes the parameter estimate, and adds variance. Notes: Error decomposition, bias-variance tradeoff, model selection: “Variance of linear model”. Practice: Q38, Q41-43.
Training error never increases as we make a (nested) model more complex, so it always favors the most complex model. We use validation error (not training error) to choose model complexity. The one-SE rule then picks the simplest model whose validation score is within one standard error of the best, since differences smaller than that may be just noise. Notes: Error decomposition, bias-variance tradeoff, model selection: “Model selection problems”, “K-fold cross validation”; One standard error rule, regularization: “One-SE rule”. HW: HW4 Q6-10. Lab: L4 Q5.
Interpreting a linear regression
\(\text{R2} = 1 - \text{MSE}/\sigma_y^2\). \(\text{R2} = 1\) is a perfect fit, \(\text{R2} = 0\) is the same MSE as predicting the mean of the \(y\) values being evaluated, and \(\text{R2} < 0\) is worse than that. For a least squares model with an intercept, the R2 on its own training data is between 0 and 1; R2 can be negative on test data, or for a model that was not fit by least squares. Notes: Linear Regression: “Interpreting R2 as explained variance”, “Interpreting R2 as error relative to”mean model”“. HW: HW2 Q1. Practice: Q19-20. Lab: L4 Q3.
For each sample, \(y_i - \bar{y}\) (its contribution to the variance) splits into an explained part \(\hat{y}_i - \bar{y}\) and an unexplained part (the residual) \(y_i - \hat{y}_i\). For a least squares model with an intercept, on its training data, the variance of \(y\) splits the same way: variance of \(y\) = explained variance + MSE, so R2 is the fraction of variance explained. Notes: Linear Regression: “Residual term”, “Interpreting R2 as explained variance”. HW: HW2 Q2. Practice: Q22.
R2 describes how well the model fits (the fraction of variance explained), not how steep the line is: a regression can have a large coefficient and a low R2, or a small coefficient and a high R2. HW: HW2 Q3. Practice: Q21.
In multiple regression (where \(x_j\) appears only in its own term, with no transformations or interactions of \(x_j\)), \(w_j\) is the change in \(\hat{y}\) associated with a one-unit increase in \(x_j\), holding the other features in the model constant. It depends on the units of \(x_j\) (so we cannot directly compare the magnitudes of coefficients of features in different units), it does not say whether the effect is causal, and it can change when other features are added to the model. Notes: Linear Regression: “Understanding the coefficients - multiple regression”. Lab: L2 Q5.
A residual \(e_i = y_i - \hat{y}_i\) is positive when the model underestimates, and negative when it overestimates. A systematic pattern in the residuals vs. a feature (whether or not that feature is in the model) shows what the model is missing: e.g. a curve suggests a non-linear transformation, a repeating cycle suggests Fourier features, a shift between groups suggests an indicator feature, and a different slope for each group suggests an interaction. Notes: Linear Regression: “Residual term”. HW: HW2 Q4-5. Practice: Q23-25. Lab: L2 Q2-5.
Least squares finds the weights that minimize the training MSE. A regularized model minimizes the MSE plus a penalty, so its training MSE is at least as large as that of least squares on the same features. HW: HW4 Q5. Practice: Q44-45.
Loss functions
Squared error grows quickly with the size of the residual, so a few large residuals (outliers) can dominate the MSE loss and pull the fit toward them. MAE grows linearly, so it is less sensitive to outliers. Huber loss is quadratic for small residuals (\(|r| \leq \delta\)) and linear for large ones, so it behaves like MSE near the fit and like MAE for outliers. Notes: Linear Regression: “Interpreting MSE, MAE”. HW: HW3 Q5-7. Practice: Q31, Q61, Q63, Q65.
The best constant prediction under MSE is the mean; under pinball loss with parameter \(\tau\) it is the \(\tau\) quantile. Pinball loss with \(\tau > 0.5\) penalizes underestimates more, so predictions shift up; with \(\tau < 0.5\) it penalizes overestimates more, so predictions shift down. Choose the loss to match the cost of each kind of error. Practice: Q31, Q64, Q66. Lab: L3 Q4-6.
Gradient descent
The training loss is not guaranteed to decrease at every iteration: if the learning rate is too large, a step can overshoot the minimum, and stochastic or mini-batch gradient descent uses a noisy estimate of the gradient. Notes: Gradient descent: “Selecting the learning rate”, “Stochastic gradient descent”. Practice: Q29.
If the learning rate is too small, the loss decreases very slowly and may not converge in the number of iterations we run; if it is too large, the loss oscillates or diverges. Check the loss curve! Notes: Gradient descent: “Selecting the learning rate”. HW: HW3 Q2. Practice: Q26, Q28. Lab: L3 Q2.
Smaller batches mean cheaper updates and more updates per epoch, but a noisier path (stochastic gradient descent bounces around in a “noise ball” near the minimum, unless the learning rate decays over time). Full batch gradient descent follows a smooth path, but each update requires the gradient for every training sample. Notes: Gradient descent: “Stochastic gradient descent”, “Mini-batch (also”stochastic”) gradient descent”, “Selecting the learning rate”, “Annealing the learning rate”. HW: HW3 Q1, HW3 Q3. Practice: Q27-28, Q59.
For stochastic gradient descent with MSE loss on a one-parameter model \(\hat{y} = wx\), the update is \(w^{t+1} = w^t + \alpha x_i e_i\) (where \(\alpha\) is the learning rate, and the constant factor 2 is absorbed into it): \(w\) increases if \(x_i\) and the residual \(e_i\) have the same sign, and decreases if they have opposite signs. Notes: Gradient descent: “Stochastic gradient descent”. HW: HW3 Q1. Practice: Q27.
When features are on very different scales, the loss surface is a “ravine”, and gradient descent oscillates across it and makes slow progress along it. Standardizing the features helps. Notes: Gradient descent: “Gradient descent in a ravine”; One standard error rule, regularization: “Standardization”. Lab: L3 Q5.
Momentum uses the history of the gradient direction: it takes larger steps in a direction where the negative gradients keep pointing, and dampens oscillations. AdaGrad and RMSProp accumulate squared gradients to give each parameter its own learning rate: smaller steps for parameters whose gradients have been large (steep directions), larger steps for parameters whose gradients have been small (flat directions). Adam combines both ideas. Notes: Gradient descent: “Momentum”, “AdaGrad”, “RMSProp”, “Adam”. Practice: Q30.
Regularization
Ridge (L2 penalty) shrinks the weights toward zero (the overall size of the weight vector decreases as \(\alpha\) increases), but does not make them exactly zero, so it is not a feature selection method; it has a closed-form solution. LASSO (L1 penalty) tends to set some weights exactly to zero (a sparse solution), which is equivalent to removing those features; larger \(\alpha\) tends to set more weights to zero. LASSO has no closed-form solution in general, so we solve it iteratively. Notes: One standard error rule, regularization: “Common regularizers”, “Graphical representation”, “Ridge term and derivative”, “LASSO term and derivative”, “Effect of regularization level”. HW: HW4 Q4, HW4 Q12. Lab: L4 Q6-7.
The intercept \(w_0\) is not included in the penalty. We standardize the features before fitting a regularized model, because the penalty depends on the size of each weight, which depends on the units of its feature. Notes: One standard error rule, regularization: “Common regularizers”, “Standardization”. HW: HW4 Q11. Practice: Q62. Lab: L4 Q6.
The regularization strength \(\alpha\) is a hyperparameter: we choose it with cross validation, not by training error (which always favors \(\alpha = 0\)). Notes: One standard error rule, regularization: “Selecting regularization level”. HW: HW4 Q9. Lab: L4 Q6.

Cross validation and model selection

To choose between candidate models (e.g. different values of the regularization strength \(\alpha\), or different numbers of features) with K-fold cross validation:

  1. Create CV folds of the training data that match the structure of the data: KFold(n_splits=5, shuffle=True) for independent samples, GroupKFold(n_splits=5) (and pass groups=... to split) when there are several samples per group, and TimeSeriesSplit(n_splits=5) for time-ordered data.
  2. Loop over folds (outer loop) and candidate models (inner loop). In each fold, fit any preprocessing and the model on that fold’s training part, and save the validation score in an array with one row per model and one column per fold.
  3. Compute the mean and standard error of each model’s validation score across folds, and find the best model (argmin for a lower-is-better metric such as MSE, argmax for a higher-is-better metric such as R2).
  4. Apply the one-SE rule: find the candidate models within one SE of the best, and pick the simplest. Check which end of your list is “simplest”: for alphas in increasing order it is the largest index; for number of features or lag order in increasing order, it is the smallest index.
  5. Refit the selected model on the full training set, and evaluate it once on the test set.

Where we practiced it: HW: HW4 Q10, HW4 Q13. Practice: Q100-109. Lab: L4 Q5-6.

alphas = np.logspace(-3, 3, 25)      # candidate models, simplest is the LAST one
nfold = 5

# Step 1: create CV folds
kf = KFold(n_splits=nfold, shuffle=True, random_state=0)

# Step 2: loop over folds, and over candidate models
scores = np.zeros((len(alphas), nfold))   # one row per model, one column per fold
for i, (idx_tr_kf, idx_vl_kf) in enumerate(kf.split(X_tr)):
    # this fold's training and validation data, before any processing
    Xtr_kf, ytr_kf = X_tr.iloc[idx_tr_kf], y_tr.iloc[idx_tr_kf]
    Xvl_kf, yvl_kf = X_tr.iloc[idx_vl_kf], y_tr.iloc[idx_vl_kf]
    # fit preprocessing on this fold's training data only
    sc = StandardScaler().fit(Xtr_kf)
    Xtr_kf_s = sc.transform(Xtr_kf)
    Xvl_kf_s = sc.transform(Xvl_kf)
    for p, a in enumerate(alphas):
        m = Ridge(alpha=a).fit(Xtr_kf_s, ytr_kf)
        scores[p, i] = mean_squared_error(yvl_kf, m.predict(Xvl_kf_s))

# Step 3: mean and standard error across folds, and the best model
mean_val = scores.mean(axis=1)
se_val = scores.std(axis=1) / np.sqrt(nfold - 1)
best = np.argmin(mean_val)                # MSE: lower is better

# Step 4: one-SE rule
target = mean_val[best] + se_val[best]    # MSE: best mean PLUS its SE
idx_one_se = np.where(mean_val <= target)[0]
p_sel = idx_one_se.max()                  # simplest = largest alpha

# Step 5: refit on the full training set, evaluate once on the test set
sc = StandardScaler().fit(X_tr)
final = Ridge(alpha=alphas[p_sel]).fit(sc.transform(X_tr), y_tr)
mse_ts = mean_squared_error(y_ts, final.predict(sc.transform(X_ts)))

The one-SE rule: four versions

There are four versions of the one-SE rule code, depending on whether the scoring metric is lower-is-better (e.g. MSE) or higher-is-better (e.g. R2), and whether the candidate models are ordered from least complex to most complex (e.g. increasing number of features, polynomial degree, or lag order) or from most complex to least complex (e.g. increasing regularization strength \(\alpha\)).

In each version, score_val is an array with one row per model and one column per fold (the validation score of model p on fold i is score_val[p, i]), and model_list = np.arange(n_models) is the list of model indices.

Where we practiced it: HW: HW4 Q6-10. Practice: Q67-71, Q100.

Lower-is-better metric (e.g. MSE), models ordered from least complex to most complex:

# threshold is: SMALLEST mean score PLUS its SE
idx_best = np.argmin(score_val.mean(axis=1))
target = score_val[idx_best,:].mean() + score_val[idx_best,:].std()/np.sqrt(nfold-1)
# candidate models have mean score BELOW that threshold
idx_one_se = np.where(score_val.mean(axis=1) <= target)
# get LOWEST indexed model (least complex)
m_one_se = np.min(model_list[idx_one_se])

Lower-is-better metric (e.g. MSE), models ordered from most complex to least complex:

# threshold is: SMALLEST mean score PLUS its SE
idx_best = np.argmin(score_val.mean(axis=1))
target = score_val[idx_best,:].mean() + score_val[idx_best,:].std()/np.sqrt(nfold-1)
# candidate models have mean score BELOW that threshold
idx_one_se = np.where(score_val.mean(axis=1) <= target)
# get HIGHEST indexed model (least complex)
m_one_se = np.max(model_list[idx_one_se])

Higher-is-better metric (e.g. R2), models ordered from least complex to most complex:

# threshold is: LARGEST mean score MINUS its SE
idx_best = np.argmax(score_val.mean(axis=1))
target = score_val[idx_best,:].mean() - score_val[idx_best,:].std()/np.sqrt(nfold-1)
# candidate models have mean score ABOVE that threshold
idx_one_se = np.where(score_val.mean(axis=1) >= target)
# get LOWEST indexed model (least complex)
m_one_se = np.min(model_list[idx_one_se])

Higher-is-better metric (e.g. R2), models ordered from most complex to least complex:

# threshold is: LARGEST mean score MINUS its SE
idx_best = np.argmax(score_val.mean(axis=1))
target = score_val[idx_best,:].mean() - score_val[idx_best,:].std()/np.sqrt(nfold-1)
# candidate models have mean score ABOVE that threshold
idx_one_se = np.where(score_val.mean(axis=1) >= target)
# get HIGHEST indexed model (least complex)
m_one_se = np.max(model_list[idx_one_se])
